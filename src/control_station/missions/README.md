# Mission files

The control station saves mission plans as `<mission UUID>.json` in this folder. Older plans in `logs/missions/` are copied here on startup if a file with the same name does not already exist.

Saving a mission also prepares a compact offline map package in `<mission UUID>_tiles/`, covering the mission boundary and route with a small margin at zoom levels 10–16. Tiles come from the USGS National Map USGSTopo service. An internet connection is required to create or refresh the package; the control station automatically switches to it when online map tiles fail. Keep the JSON file and its matching tile folder together when copying or backing up missions. Deleting a mission also deletes its tile folder.

Each collection checkpoint has a **5 m arrival circle**. Transit points have `collect_data: false` and do not start a recording. `auto_collection_seconds` sets the duration for generated checkpoints. The station stores targets in `waypoints`, and derives `planned_route` and `return_route` from Home through every target to End (or Home). It adds only the turning points needed by the shortest in-boundary connector, using a 5 m margin for manual missions or the configured automatic clearance for automatic missions; it does not add routine points along long, straight legs. The upload includes this compact ordered route, subject to the buoy's 64-point limit. Current buoy firmware still inhibits propulsion in Mission mode, so it does not execute these points yet.

Home and an optional End point must be inside the survey boundary (with the route clearance margin). When `end` is absent or null, Home is the effective mission endpoint. The derived route constrains travel from Home to the first target, between targets, and from the final target to End/Home to remain inside the boundary. The final return segment is highlighted as a dashed route in Mission Creation. Return-route triggers are stored as planned failsafes and are not active until firmware navigation is implemented.

Boundary edits automatically uncross connecting edges while retaining the placed coordinates. A new or moved boundary point within 2 m of another boundary point is ignored so the outline does not collapse into overlapping vertices. The planner may change boundary point order after an edit; review the shaded survey area before saving.

For mission audio, keep one original WAV segment per checkpoint rather than appending new recordings to a single file. A future recording manifest should identify each segment by mission ID, checkpoint index, planned and actual GPS position, UTC start/end time, sample rate, channels, and file name. The station can then build a single export in checkpoint order from the segments, with the manifest preserving the actual gaps between stops. Original segments remain the source of record.
