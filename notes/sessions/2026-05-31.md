### Meeting Notes

- The RCWL-1655 is documented as a `3.3V` ESP32 sensor so the echo line stays within safe logic range.
- `GPIO39` is a good echo input because it is input-only.
- `GPIO13` is now reserved for the ultrasonic trigger line in the current wiring plan.
- The existing control station already understands `RANGE` packets, so the new firmware output should show up in the depth field without further UI changes.
- `GPIO14` is now the DS18B20 data pin, which avoids the boot-strap risk from the earlier `GPIO0` option.
- `VP / GPIO36` is now the INMP441 microphone data pin and is input-only, which matches the microphone output.

### Meeting Notes

- A multimeter reading of ~3.28V only confirms the D14 bus is pulled high at idle.
- A steady high level does not prove the sensor is responding on the 1-Wire bus.
- If the serial probe reports `NO_PRESENCE`, the fault is on the 1-Wire communication path, not just the water immersion side.
- The ADC issue was in the firmware, not the hardware, because the boot-time ADC calibration and config path was still triggering the core 3.x ADC conflict.
- The current workaround uses direct ADC1 reads on GPIO34 and GPIO35 instead of Arduino `analogRead()`.
